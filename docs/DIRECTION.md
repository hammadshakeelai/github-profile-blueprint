# Design direction

Three concepts, each built from real projects, rendered by GitHub, and captured
at both widths in both schemes. The pick is **C · Tabs**, with A's markdown
discipline folded in.

Comps: [comp-a](direction/comp-a/README.md) · [comp-b](direction/comp-b/README.md)
· [comp-c](direction/comp-c/README.md) — all generated by
`tools/direction/build.py` from [content.json](direction/content.json).
Screenshots in [direction/shots/](direction/shots/).

## The brief the survey set

Nobody in 446 surveyed profiles was both visually ambitious and legible on a
phone. That gap is the target, so every comp had to satisfy the same rules,
each traceable to evidence:

| Rule | Evidence |
|---|---|
| Every SVG readable at 309px — text ≥ 22 units in a 600-wide viewBox | 55% of surveyed cards have their largest text under 11px on a phone; 90% of those only because the phone shrank them |
| Markdown carries the reading; SVG carries identity | Real text reflows; an SVG panel just scales down |
| Dark and light pairs through `<picture>` | Verified in Chromium, Firefox and WebKit |
| Committed files only — no hosted generators | Free-tier services are the biggest single cause of breakage (309 dead image URLs) |
| No image tables for layout | On a phone GitHub either crushes cards to 76px or scrolls the table sideways |
| The first frame is the whole composition | A one-shot reveal rendered at desktop width and showed an empty panel at phone width, in two captures of the same page |
| No `gradientTransform` animation | WebKit never animates it |
| No star counts or invented metrics | The repositories have no stars to show, and fake numbers read as dishonest |

## The three

### A · Index — restrained and typographic

A serif wordmark, one accent rule, then grouped markdown lists: name, one line,
a live link and a source link. No panels, no motion.

**Strong:** the most readable of the three at any width, because almost all of
it is real text. Ages well. Cheapest to maintain — one SVG.
**Weak:** it is also the most familiar. The survey found four profiles sharing
one "Index Nº 001" layout of exactly this kind; done plainly, it reads as
competent rather than memorable.

### B · Boot — dense instrument panel

A boot log that lists the systems, a process monitor of every project with
live/source markers, then `<details>` for depth.

**Strong:** density with legibility; the monitor makes thirteen projects
scannable in one panel. Suits someone who builds operating systems.
**Weak:** the most crowded genre in the survey — terminal and HUD profiles are
everywhere (Dhyanesh006, SergiGTAr, 10ishk, getaudra, JackLuciano). It also
states categories rather than inviting a click.

### C · Tabs — the unexpected one

Every project is a browser window with its own address bar, and the whole card
is a link to the running thing. Chosen.

**Strong:**
- **Nothing in the survey looks like this.** Terminals, dashboards and stat
  cards are everywhere; a profile built as a stack of browser windows is not.
- **It comes from the work itself.** Eleven of the thirteen catalogued projects
  ship a live demo on `github.io` — whole Linux systems, three.js games, 8086
  assembly in DOSBox. The form states the through-line: it all runs in a tab.
- **It uses the only interaction GitHub allows.** An SVG can't be clicked
  inside, but an image can be wrapped in a link, so each window is a door to
  something running. The survey found interactivity rare and, where present,
  plain (marcizhu's chess board).
- **Phone-first by construction:** cards stack in one column, each is a large
  tap target, every line clears the legibility floor.

**Weak, and accepted:** repeated window chrome risks monotony, and eight cards
make a long page on a phone. Mitigated by capping the cards at six and listing
the rest as text.

## What ships

C, with A's discipline:

1. A window header — name, one line of what the work is.
2. **Six** project windows, each a link to its live demo.
3. Everything else as grouped markdown lists (A's pattern): name, one line,
   live link, source link.
4. A one-line footer to the main profile.

Motion: none beyond a blinking cursor in the header. Every panel has a dark and
a light file behind `<picture>`. Nothing is fetched from a third party.

## What it deliberately leaves out

- **Stats of any kind** — no stars, commits, streaks, language rings. The
  repositories have no stars, and the survey's most-copied stat card is dead.
- **Contribution art** — snake, pacman, 3D graphs. All are Action-maintained
  and none says anything specific about this work.
- **Badges.** 42% of surveyed profiles are more than half badges; none of them
  is more legible for it.
- **A typing banner.** 54% of `readme-typing-svg` instances are illegible on a
  phone, and the effect says nothing the header can't.
- **Anything hosted elsewhere.** Every image is committed to the repository.

## Changing the pick

All three are generated: `python tools/direction/build.py` rebuilds them from
`content.json`. Swapping the shipped design means building from a different
comp, not restarting — the rules above are shared by all three.
